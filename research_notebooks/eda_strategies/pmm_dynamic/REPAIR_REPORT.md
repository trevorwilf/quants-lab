# PMM Dynamic Bayesian Optimization Codebase — Repair Report (v3)

Date: 2026-03-05

This report documents the additional fixes applied after a user-reported failure when running `pmm_dynamic_optimize - GPU.ipynb` (cell 6 parity gate).

## What the user reported

When running the GPU notebook parity gate, the notebook aborted with:

- Repeated warnings:

  `validate_candles failed: STRICT: 157 rows violate OHLC sanity (low > min(O,C) or high < max(O,C) or non-positive price).`

- CPU/GPU parity failures with large deltas, e.g. `n_trades` mismatching (CPU hundreds of trades, GPU 0), and very large Sharpe differences.

The notebook then raised:

`RuntimeError: GPU/CPU parity failed. Fix before running optimization.`

## Root cause diagnosis (most likely)

### 1) Synthetic candle generator created invalid OHLC rows

The notebook parity gate uses synthetic candles generated by `pmm_dynamic_optimizer_parity_test.generate_synthetic_candles()`.

The previous generator built:

- `close = prices`
- `open = prices * (1 +/- 0.003)`
- `high = prices * (1 + uniform(0.001..0.01))`
- `low  = prices * (1 - uniform(0.001..0.01))`

This construction **does not guarantee** `high >= max(open, close)` and `low <= min(open, close)`, so a non-trivial fraction of rows violate OHLC sanity.

On CPU this can still “work”, but it pollutes the parity gate and can amplify CPU/GPU path differences.

### 2) CuPy/Numba CUDA context mismatch on some systems

`pmm_dynamic_optimizer_gpu.py` previously defaulted to using CuPy arrays **whenever CuPy was importable**.

On some machines/environments (notably “kitchen sink” research environments), CuPy can be installed against a CUDA runtime/toolkit that does not match Numba's expectations (or contexts can be isolated). In that situation:

- The kernel can run but **read incorrect device memory** (or see unexpected values),
- Leading to *massive* parity divergence (e.g., GPU sees volume=0, prices wrong, params wrong, etc.),
- Often without a clean crash.

This matches the reported symptom: some test cases "pass" only because both CPU and GPU produce 0-trade outputs, while cases requiring active trading diverge heavily.

## Fixes implemented (v2)

### Fix A — enforce OHLC sanity in synthetic candle generators

File: `pmm_dynamic/pmm_dynamic_optimizer_parity_test.py`

- Added a deterministic post-processing step in **all** candle generators:

  - `high = max(high, open, close)`
  - `low  = min(low, open, close)`
  - clamp all prices to positive epsilon

This removes the `STRICT: ... rows violate OHLC sanity` failure mode from the parity gate.

### Fix B — default GPU array backend to Numba device arrays (CuPy opt-in)

File: `pmm_dynamic/pmm_dynamic_optimizer_gpu.py`

- Introduced explicit backend selection via environment variable:

  - Default: `PMM_DYNAMIC_GPU_BACKEND="numba"`
  - Optional: `PMM_DYNAMIC_GPU_BACKEND="cupy"`

- CuPy is now **opt-in** only. If you do not set `PMM_DYNAMIC_GPU_BACKEND="cupy"`, the code uses:

  - `numba.cuda.to_device(...)` for transfers
  - Numba device arrays for output buffers

This is the safest path for correctness and parity across environments.

### Fix C — deterministic regression test for backend selection

File: `pmm_dynamic/test_gpu_backend_selection.py`

- A minimal test that injects a dummy `cupy` module and uses `NUMBA_ENABLE_CUDASIM=1` so it runs on CPU-only machines.
- It verifies:
  1) default backend is `numba` even when cupy is importable
  2) backend switches to `cupy` only when explicitly requested

This test **fails on the old code** (where CuPy was auto-selected) and **passes on v2**.


### Fix D — log candle QA warnings only once per process

File: `pmm_dynamic/pmm_dynamic_optimizer.py`

- `validate_candles()` intentionally emits a TIMESTAMP SEMANTICS warning (it cannot auto-detect open-time vs close-time candles).
- Previously, `PMMDynamicBacktester.run()` logged this warning **on every trial** which can flood logs during Bayesian optimization.
- Added a small guard (`_SEEN_VALIDATE_WARNINGS`) so each unique candle QA warning is logged **once per process**, preserving safety information without spamming.

# v3 follow-up: real-GPU parity still failing on some systems

After applying v2, the parity gate could still fail on some real GPU environments with symptoms like:

- CPU produces hundreds of trades, GPU produces 0–1 trades
- GPU PnL matches “no-trade / hold inventory” PnL for some test cases
- Failures are **large** (not floating point noise)

Given that v2 parity passes under `NUMBA_ENABLE_CUDASIM=1`, the remaining failures are most consistent with a **backend/context/stream issue** (especially when CuPy is installed) or a **dtype ABI edge-case** in certain Numba CUDA builds.

## Fixes implemented (v3)

### Fix E — synchronize CuPy transfers before launching Numba kernels

File: `pmm_dynamic/pmm_dynamic_optimizer_gpu.py`

Added `_cupy_synchronize()` and called it:

- after CuPy-based transfers in `prepare_candles_gpu()`
- after CuPy-based transfers in `_pack_params()`
- immediately before and after the `_simulate_kernel` launch in `gpu_backtest_single()`

Why: when `PMM_DYNAMIC_GPU_BACKEND='cupy'`, `cp.asarray(np_array)` can enqueue host→device copies on a non-default stream (e.g., per-thread default stream). Numba kernels typically launch on the default stream. Without an explicit sync, the kernel can read partially-copied/stale parameter buffers, leading to catastrophic parity failures.

### Fix F — pack integer params as float64 for cross-backend stability

File: `pmm_dynamic/pmm_dynamic_optimizer_gpu.py`

Changed these packed arrays from `int32` → `float64`:

- `p_macd_fast`, `p_macd_slow`, `p_macd_signal`, `p_natr_length`
- `p_n_levels`

The CUDA kernel already casts them to `int(...)` on-device.

Why: some environments show subtle dtype/ABI inconsistencies (especially when mixing CuPy + Numba). Packing as `float64` removes integer-array ABI ambiguity and makes parameter buffers uniform.

### Fix G — fix timestamp sorting alignment bug in `prepare_candles_gpu()`

File: `pmm_dynamic/pmm_dynamic_optimizer_gpu.py`

Moved the computation of `ts_vals` to occur **after** sorting the dataframe by timestamp.

Why: previously, if input candles were not already sorted, prices would be sorted but timestamps would remain in the original order, creating a silent OHLCV↔timestamp misalignment on GPU.

### Fix H — force Numba backend in the GPU notebook

File: `pmm_dynamic/pmm_dynamic_optimize - GPU.ipynb`

Added:

```python
os.environ["PMM_DYNAMIC_GPU_BACKEND"] = "numba"
```

and printed backend info at notebook startup.

Why: the notebook should be deterministic and safe by default. It now overrides any `.env` setting and ensures the stable Numba device-array backend is used.

### Fix I — improve parity failure messages with backend/device info

File: `pmm_dynamic/pmm_dynamic_optimizer_gpu.py`

When parity fails, the exception message now includes:

- selected backend (`numba` vs `cupy`)
- `get_gpu_info()` payload

Why: makes real-GPU failures diagnosable without guessing.
